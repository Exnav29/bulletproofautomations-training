## Architectural conclusion

The implementation extends the existing site and reuses admin authentication/shell, Hostinger sender, database helpers, payment regions, and credential/entitlement records. Separate workshop registration records and Paystack business are justified because cohort enrollment has constrained programme options, installment behavior and unsafe email fallback matching in its production webhook. Nine protected cohort payment/middleware files were byte-identical to main. **No large rewrite required.** Risks concern transactional ordering, concurrency, external side effects, operational recovery.

## Seven original HIGH findings (must correct)

1. **Duplicate partial refund application:** Two concurrent deliveries both see `matched=false`; refund RPC serializes on registration/attempt but does not recheck event application, so one GHS 50 refund can count as GHS 100. Reproduced through two concurrent signed refund deliveries. Correct by locking/checking the payment event's applied state *inside* the refund transaction with consistent lock order. References: [supabase/functions/workshop-paystack-webhook/index.ts:125-160](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/functions/workshop-paystack-webhook/index.ts#L125-L160); [supabase/migrations/20261103120000_workshops.sql:628-655](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261103120000_workshops.sql#L628-L655).
2. **Refund before charge discarded:** If `received_minor=0`, refund is marked matched/`already_refunded`; later charge may confirm registration despite refund; webhook ignores replay. Hold pending refund until its charge is applied and reconcile atomically. [supabase/migrations/20261103120000_workshops.sql:639-645](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261103120000_workshops.sql#L639-L645).
3. **Waitlist offer/checkout renewed beyond 24 hours:** Existing-registration shortcut bypasses offer-token check. An initialized checkout can repeatedly create fresh 30-minute holds even after offer expiry, potentially blocking later FIFO attendees for days. Forbid extending absolute offer deadline, while reconciling legitimate in-flight payments. [supabase/migrations/20261111120000_workshop_waitlist.sql:186-196](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261111120000_workshop_waitlist.sql#L186-L196); [supabase/migrations/20261111120000_workshop_waitlist.sql:309-321](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261111120000_workshop_waitlist.sql#L309-L321).
4. **Payment reconciliation starvation:** Dispatcher always selects oldest 10 `initialized` attempts; abandoned attempts block newer successful ones; excludes `init_failed` and attempts older than 48 hours. Fair rotation and durable unresolved-payment review needed. [functions/api/_workshops.js:398-409](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/functions/api/_workshops.js#L398-L409).
5. **Concurrent waitlist emails invalidate links:** Waitlist mail selection has no atomic claim. Two workers mint different tokens and overwrite hash; both emails send, first unusable. Claim atomically, keep stable token across workers/retries. Mocked reproduction produced two accepted emails but only one usable link. [supabase/migrations/20261111120000_workshop_waitlist.sql:626-656](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261111120000_workshop_waitlist.sql#L626-L656); [functions/api/_waitlist.js:81-93](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/functions/api/_waitlist.js#L81-L93).
6. **Overlapping Google Calendar account changes leave unauthorized guests:** ETags protect Google writes but not freshness of DB plans. Concurrent A→B and A→C can leave B and C in Calendar while only C is tracked, hence B can't be removed on later refund. Serialize per registration, version desired account, reconcile stale writes against actual attendees. Mocked valid-ETag reproduction verified orphan. [supabase/migrations/20261110120000_workshop_calendar_sync.sql:41-77](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261110120000_workshop_calendar_sync.sql#L41-L77); [functions/api/_calendar.js:66-88](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/functions/api/_calendar.js#L66-L88); [supabase/migrations/20261110120000_workshop_calendar_sync.sql:93-104](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/supabase/migrations/20261110120000_workshop_calendar_sync.sql#L93-L104).
7. **Dispatcher launch switch command is ineffective:** Runbook replaces `webinar-e2e-test...` but deployed job targets `webinar-e2e-test-r2...`; no-op would leave live work routed to rehearsal. Runbook incorrectly claims release 2 unapplied; actual read-only inspection said releases 1/2 applied. Derive command from live config, assert target explicitly. [docs/workshops-runbook.md:376-381](https://github.com/Exnav29/bulletproofautomations-training/blob/78a707bc589e05f277d8722b5f6181940954e068/docs/workshops-runbook.md#L376-L381).
